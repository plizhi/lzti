## 一、最终走的是哪条路（不是「授权推送」）

服务器侧 `pre-push` hook（`/home/pupeng/projects/lzti/.git/hooks/pre-push`，三个 worktree 共用）规定：

```
允许：推 server-work        禁止：推 dev-work / master
紧急授权：ALLOW_SERVER_PUSH=1 git push origin <branch>   （需朋大大明确同意）
```

hook 原文里写明了流程与例外：

> 笔记本是独立 clone，没有这个 hook → 笔记本的 push 不受影响。
> 规则：改动权在笔记本。服务器侧请推到 server-work 分支，笔记本联网后 fetch、审阅，再合入 dev-work。

**本次没有动用 `ALLOW_SERVER_PUSH`**，而是**在笔记本上完成 fetch → 审阅 → 合入 → 推送**，
即 hook 所设想的「乙」路径。服务器侧 agent 只做到「推到 server-work」为止，
推送这一步由笔记本接手，规则与意图均未被绕过。
