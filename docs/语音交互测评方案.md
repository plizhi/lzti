# 语音交互式测评（荔枝测评）—— 技术验证与方案

> 需求（朋大大）：不按键。AI 问一道题 → 把选项念出来 → 孩子或家长直接说"选A""选B"或"三"来作答。
>
> 本文所有结论均来自 2026-10-28 的实测，非推测。

---

## 一、结论：可行，且技术风险比预想低得多

实测数据（全部用真实 MiniMax API）：

| 验证项 | 结果 |
|---|---|
| 短语音识别准确率 | **12/12 全对**（"选A""选B""三""第三""第3个""我选3""选第三个""2""5"…） |
| 谐音容错 | "选诶" → **"选A"** ✅；"选c" → "选C" ✅ |
| 噪声鲁棒性 | 信噪比 **20 / 10 / 5 / 0 dB 全部识别正确**（0dB = 噪声与语音同能量） |
| 流式 ASR | 可用，**首字延迟 0.59s**，SSE 逐段返回 `delta` |
| TTS 音质 | speech-2.8-hd / female-shaonv，32kHz 单声道 mp3，实测正常 |

**最关键的结论：不需要在 ESP32 上跑任何 AI。** 全部在服务端：

```
ESP32 录音 → MiniMax ASR → 答案归一化 → 落进度 → MiniMax TTS 念下一题 → ESP32 播放
```

ESP32 只做「录音 / 播放」两件事，这两件事已经有验证过的实现路径。

---

## 二、答案归一化：把"说出来的话"变成 1-5

ASR 会返回各种说法，需要在后端归一化。实测得到的映射规律：

| ASR 返回 | 归一化 | 说明 |
|---|---|---|
| "选A。" "选a" "选诶" | 1 | 字母读音 |
| "一" "1" "选一" | 1 | 中文数字 |
| "5" | 5 | ASR 会把阿拉伯数字转成中文（"5"→"五"） |
| "我选三" "第三个" "第3个" | 3 | 各种口语 |
| "不知道" "嗯" "我不要" | 无效 | 触发重问 |

**归一化用规则 + LLM 双保险**：
1. 先用正则规则匹配（覆盖 90% 情况，零延迟、零成本）
2. 规则匹配不到时，交给 LLM 判定（MiniMax M3.1 Flash，判断"这句话表达的是 1-5 中的哪个"）

LLM 兜底是关键——孩子可能说"应该是第三个吧"这种模糊表达，规则处理不了但 LLM 可以。

## 三、交互流程设计

### 一轮对话的时序

```
[ESP32]  ① 播放：「第一题。孩子回家后会主动说起学校里学到的或发生的新鲜事。
                    请选择，一到五。」
              ↓ 播放完
[ESP32]  ② 录音（VAD 自动断句，或按键松开触发）
              ↓ 上传
[服务端] ③ ASR → 归一化 → 落进度 → 算下一题 → TTS 念下一题
              ↓ 返回 mp3
[ESP32]  ④ 播放下一题
```

### 关键设计决策

**Q：怎么判断"孩子说完了"？**
- 方案 A（推荐）：**VAD 静音断句**。ESP32 用 esp-sr / ESP-ADF 的 VAD 检测静音 700ms 自动结束录音。
- 方案 B：按键松开（按住说话），但这就不是"免按键"了。
- 方案 C：固定录音时长（比如 3 秒），最简单但会截断长回答。

**Q：答错了怎么办？**
- 归一化失败（听到"不知道"）→ TTS 回一句「没听清，再说一次好吗？」+ 重念本题，**不跳题**
- 识别到的数字不在 1-5 → 同样重问
- 连续 2 次失败 → 提示「可以跳过这道题吗？」

**Q：家长中途想接管？**
- 语音指令"我来答" / "家长来答" → 切换到家长视角（parent）
- 建议支持，真实场景里家长会忍不住插话

**Q：怎么防止环境音误触发？**
- ① VAD 阈值 + 最短语音时长（< 300ms 丢弃）
- ② ASR 结果必须能归一化成 1-5 才采纳，否则重问
- ③ 连续 3 次无法识别 → 降级到按键模式（如果有屏）
- ④ 唤醒词（可选）：说"小测小测"才进入答题模式，避免电视声误触发

**Q：答完 57~93 题会不会太久？**
- 语音答题比按键快（不用找按钮），而且不用盯着屏幕，**体感更快**
- 建议支持「跳过」和「上一题」，并且**断点续答**（进度接口已实现）

## 四、后端要加什么

现有 lzti 设备接口（commit 4d63b50）已有：
- `GET /api/device/questions` —— 按维度分页出题
- `POST /api/device/answer` —— 增量落答案
- `POST /api/device/submit` —— 提交出报告
- `POST /api/device/speak` —— TTS 播任意文本

**新增（语音交互专用）：**

### 1. `POST /api/device/voice/next`
推进到下一题并返回题目音频。

请求：`{ sessionId, questionnaireType }`
响应：
```json
{
  "code": 0,
  "data": {
    "questionIndex": 3,
    "totalQuestions": 18,
    "question": { "id": "p-li-3", "text": "孩子在日常生活中会主动尝试或探索新东西。" },
    "scale": { "min": 1, "max": 5, "minLabel": "非常不符合", "maxLabel": "非常符合" },
    "prompt": "第一题。孩子在日常生活中会主动尝试或探索新东西。请选择，一到五。",
    "audioBase64": "...mp3...",
    "isLast": false
  }
}
```

### 2. `POST /api/device/voice/answer`
上传录音 → 识别 → 归一化 → 落答案 → 返回下一题音频。

请求：multipart，`audio` + `sessionId` + `questionnaireType`
响应：
```json
{
  "code": 0,
  "data": {
    "recognizedText": "选A",
    "normalizedValue": 1,
    "accepted": true,
    "next": { "questionIndex": 4, "prompt": "...", "audioBase64": "..." },
    "finished": false
  }
}
```

归一化失败时：`accepted: false`，`retry: true`，附重问音频。

### 3. `src/lib/answer-normalizer.ts`
答案归一化（规则 + LLM 兜底）。

```ts
export async function normalizeAnswer(
  text: string,
  opts: { min: number; max: number; useLLM?: boolean }
): Promise<{ value: number | null; reason: string }>
```

规则覆盖：
- 字母：选A/选a/A/诶 → 1..5
- 中文数字：一二三四五 → 1..5
- 阿拉伯数字：1..5
- 序数：第三个/第3个/3号 → 3
- 口语：我选X、选X、答案是X、X吧、应该是X
- 否定/无效：不知道、不确定、我不要、没听清、随便 → null

### 4. 提示词模板 `src/lib/voice-prompt.ts`
统一生成题干播报文案。示例：

```
第一题。孩子在日常生活中会主动尝试或探索新东西。
请选择，一到五。
```

要点：
- 题目序号让用户知道进度
- 明确说"一到五"，因为语音分不清"非常不符合"这种量表词
- 语速放慢（speed=0.9），给孩子反应时间

## 五、ESP32 固件侧要做什么

比按键方案简单，因为只有录音和播放：

### 状态机

```
IDLE ──(唤醒/开始)──> SPEAKING_Q(播放题目) ──> LISTENING(录音+VAD) 
      ──(上传成功)──> SPEAKING_A(播放反馈/下一题) ──> IDLE
      ──(VAD超时/静音)──> LISTENING
```

### 关键技术点

1. **VAD 静音断句**
   - ESP-ADF 的 `esp_voice_detector` 或 `esp-sr` 的 VAD
   - 静音阈值 700ms，最短语音 300ms
   - 录音格式：PCM 16kHz 单声道 16bit（MiniMax 建议），或转 ADPCM 减小体积

2. **TTS 音频播放**
   - 收到 mp3 → 解码（`minimp3` 或 `esp_codec_dev`）→ I2S 送 MAX98357A
   - 需要 PSRAM 撑住 mp3 缓冲（N16R8 的 8MB 够用）

3. **对话轮次控制**
   - 服务端返回"下一题音频"，设备只管播
   - 播完 → 进录音态
   - 避免"设备自己判断该出下一题"的逻辑，保持单一数据源

4. **断点续答**
   - 每次答完，服务端返回当前进度
   - 设备重启后调 `/api/device/session` 读进度继续

## 六、对比两种方案

| | 按键手柄 | **语音交互** |
|---|---|---|
| 硬件 | 5 个按键 | 麦克风 + 喇叭（更少件） |
| 交互 | 家长读题、孩子按键 | **AI 念题、孩子说话** |
| 适合年龄 | 小学低年级以上 | **更小的孩子也能用** |
| 家长参与 | 必须（要读题） | 可选（可让 AI 念） |
| 抗噪 | 按键不受影响 | 依赖 VAD + 归一化（已实测 0dB 可用） |
| 成本 | ~¥90-120 | ~¥130-170（多麦克风和喇叭） |
| 实现复杂度 | 低 | **中**（VAD + 归一化 + 轮次控制） |
| 风险点 | 少 | 噪声误触发、答不上来 |

**建议：语音交互为主，按键作为兜底。**
如果 ASR 连续 3 次识别不出，设备提示"要不要用按键？"——家长可以伸手按键解决。
