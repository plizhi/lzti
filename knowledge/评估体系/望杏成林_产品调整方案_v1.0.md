## 一、产品背景与目标

### 1.1 现有产品定位
望杏成林（wxcl.nzyy.cc）是一款亲子陪伴产品，Slogan："让我们一起在时光里，望杏成林"。核心价值是帮助家长在日常互动中更有方向地陪伴孩子成长。

### 1.2 本次调整目标
将产品从"以AI问答为核心"调整为"以每日照料记录为核心"，让家长每次打开app都像走进自己的杏林，通过记录日常亲子互动，获得AI驱动的个性化反馈与成长指引。

### 1.3 核心理念
**打开望杏成林 = 走进杏林浇水施肥**

每一次记录 = 浇一次水
AI反馈 = 告诉你今天哪棵树在长、哪棵树需要阳光
两个轴 = 成全孩子（目的地）+ 养护关系（那条路）

## 二、核心框架（后台分析，家长无感知）

### 2.1 轴一：对孩子的成全（5个维度）

| 维度 | 含义 |
|------|------|
| 热情与好奇心 | 孩子是否对新事物表现出好奇与热情 |
| 识风险知进退 | 孩子是否展现出风险认知和决策能力 |
| 勇气与力量 | 孩子面对困难是否有应对的勇气 |
| 天赋与机遇 | 孩子的天赋是否被识别、资源是否被善用 |
| 享受其中 | 孩子是否沉浸在令他享受的事情中 |

### 2.2 轴二：亲子关系的养护（5个要素）

| 要素 | 含义 |
|------|------|
| 自主 | 双方是否保有各自的自主空间 |
| 实事求是 | 互动是否基于事实而非评判 |
| 自我负责 | 双方是否各自为自己的情绪和行为负责 |
| 建设性 | 互动是在建立还是在拆毁 |
| 同情心 | 双方是否彼此感受到被理解、被看见 |

## 三、功能规格

### 3.1 核心功能：每日照料记录

**入口：** 登录后默认落地页（替代现有首页）

**页面元素：**
- 顶部：一句话引导语"今天和孩子发生了什么？"
- 中间：一个文本输入框（不限字数，建议200-500字）
- 底部："记录今日" 按钮
- 下方：历史记录列表（可展开查看历史报告）

**交互流程：**
1. 家长输入一段亲子互动记录（可以是今天的，也可以是回忆）
2. 点击"记录今日"
3. 页面展示"杏林分析中…"动画（2-3秒）
4. 展示今日照料报告
5. 报告支持"继续添加记录"或"返回"

**输入灵活性：**
- 支持一次性输入多段记录（批量模式，用于新用户初始化）
- 支持历史记录的回溯输入

---

### 3.2 核心功能：每日照料报告

**报告结构（面向家长）：**

```
🌿 今日杏林

[整体状态一句话]

[轴一：今日成全孩子的状态]
- 热情与好奇心：🌱 [描述]
- 识风险知进退：🌿 [描述]
- 勇气与力量：🌲 [描述]
- 天赋与机遇：✨ [描述]
- 享受其中：☀️ [描述]

[轴二：今日关系养护状态]
- 自主：💧 [描述]
- 实事求是：🌾 [描述]
- 自我负责：🌳 [描述]
- 建设性：🏡 [描述]
- 同情心：💛 [描述]

✨ 今日亮点
- [亮点1]
- [亮点2]

🌱 机会窗口
[维度/要素名称]：[描述]
建议：[具体的下一步行动，30字以内]

💬 给你的一句话
[杏林意象的鼓励语，50字以内]

❓ 留给你一个问题
[追问，30字以内]
```

**视觉规范：**
- 使用杏林绿色系作为主题色
- 每个维度用emoji表示（🌱🌿🌲✨☀️💧🌾🌳🏡💛）
- 不出现雷达图、分数、数字评分
- 报告整体风格温暖、有底蕴，像朋友在说话

---

### 3.3 功能：全景报告

**入口：** 报告中或底部导航的"全景报告"按钮

**功能描述：**
- 家长手动选取一段时间（最近7天/30天/全部）内的多条记录
- 一键生成综合分析报告
- 展示：该时段内杏林的整体变化、各维度/要素的成长曲线、亮点总结
- 数据量限制：选取"全部"时最多取最近90条；不足3条时提示"记录太少，无法生成全景报告"

**交互流程：**
1. 点击"生成全景报告"
2. 选择时间范围（最近7天/30天/自定义）
3. 展示"正在生成…"状态（可设置超时提示）
4. 生成综合报告（格式同每日报告，但为综合视角）

---

### 3.4 功能：周报（自动化）

**触发时机：** 每周日21:00推送（如无记录则不推送、不生成，过期不补）

**功能描述：**
- 系统自动汇总本周所有记录
- 生成一份"本周杏林周报"
- 推送到家长的消息列表或首页
- 若本周无记录，则不生成、不推送

**周报结构：**
- 本周杏林整体状态（一句话）
- 各维度/要素的本周变化趋势
- 本周最值得记住的一个时刻
- 下周可以关注的一个窗口

---

### 3.5 新用户引导

**首次登录：**
- 引导家长一次性输入5-10段自己印象深刻的亲子互动
- 后台批量分析后，生成"初始画像"
- 展示时附说明："这是你给这片杏林画的初始地图，之后每天记录都会让这幅地图更完整"

**引导文案：**
> 欢迎来到望杏成林。这里是你和孩子一起成长的那片杏林。
>
> 第一次来，可以把你记得的、和孩子的一些互动时刻写下来。不用在意写得好不好，真实就好。
>
> 写完之后，你会看到一片属于你的杏林地图。

## 四、AI分析模块

### 4.1 调用策略

**模型：** DeepSeek v4-flash
**调用方式：** streaming输出（首字延迟1-2秒，逐字展示）
**响应时间目标：** 3-5秒内开始输出

### 4.2 Prompt设计

**输入：** 家长的一段亲子互动记录（中文，200-500字）

**输出：** JSON格式，strict_json=true

```json

    "dimension_4_天赋与机遇": {...},
```

### 4.3 Prompt存放位置

后端 `data/ai/daily-care-prompt.md`，便于后续维护和迭代。

### 4.4 完整版必须实现的优化

1. **流式输出（streaming）**：必须实现。技术选型由开发自行判断（SDK支持用SDK，不支持自实现SSE）
2. **缓存机制**：Redis，key = `daily_care:{user_id}:{date}`，TTL 24小时
3. **异步预生成**：用户提交后，后台异步调用API，前端先展示骨架屏
4. **历史记录复用**：批量输入时，多段记录合并为一次API调用

**批量导入限制：**
- 最多10段，每段上限300字（超过截断）
- 不足5段也可提交，前端做校验

## 六、技术要求

### 6.1 数据存储

**新增表结构：**

```sql
-- 每日照料记录表
CREATE TABLE daily_care_record (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    content TEXT NOT NULL,          -- 家长输入的原始记录
    report JSONB,                   -- AI分析报告（JSON）
    report_generated_at TIMESTAMP,  -- 报告生成时间
    created_at TIMESTAMP DEFAULT NOW()
);

-- 周报表
CREATE TABLE weekly_report (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    week_start DATE NOT NULL,      -- 周起始日期
    report JSONB NOT NULL,         -- 周报内容
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 6.2 API设计

**POST /api/v1/daily-care/analyze**
- 输入：{ "content": "家长记录的文字" }
- 输出：AI分析报告JSON（流式）
- 逻辑：调用DeepSeek API，返回分析结果，存入daily_care_record表

**GET /api/v1/daily-care/records**
- 输入：user_id, page, limit
- 输出：记录列表（含简要报告）

**GET /api/v1/daily-care/report/:id**
- 输入：record_id
- 输出：完整报告

**POST /api/v1/daily-care/comprehensive**
- 输入：{ "record_ids": [...] } 或 { "start_date": "", "end_date": "" }
- 输出：全景综合报告（流式）

**POST /api/v1/daily-care/batch-import**
- 输入：{ "records": ["记录1", "记录2", ...] }
- 输出：初始画像报告（流式）

**GET /api/v1/daily-care/weekly-report**
- 输入：user_id
- 输出：本周周报（若无则生成）

### 6.3 性能要求

- API响应时间：P95 < 8秒
- 页面首屏加载：< 2秒
- 流式输出首字延迟：< 2秒

### 6.4 JSON解析容错要求

- 后端必须对AI返回的JSON做容错处理
- 字段缺失或格式异常时，使用默认兜底描述（"今天杏林状态平稳"），不允许报错或返回空
- 所有异常情况需记录日志，便于后续优化Prompt
